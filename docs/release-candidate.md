# 候选包与回退包

当前不把编译成功的源码快照称为稳定发行版。发行资料分为两类：

- **复现候选**：固定源码提交、工具版本、构建结果及逐文件校验值。实机未复测
  的项目明确列为未复测；BW16 使用认证模板编译的镜像只能放在
  `compile-checks/` 并标记 `DO_NOT_FLASH`。
- **本地回退包**：保存此前操作者确认过的精确固件和客户端。不因为整理了
  文件就把它改称最新版本；旧固件可能内含旧设备认证配置，不公开上传。

上述历史来源和最新 GitHub 源码不是同一个提交。包内清单分别记录源代码提交、
每项制品的来源提交、哈希和验收状态；不能声称最新源码必然重建出上述指纹。
编译器路径、调试信息、认证配置等都可能影响完整二进制指纹，不能据此擅自
判断差异全都无害，也不能把不同哈希的文件当作同一份验收产物。

## 打包要求

`tools/package_release_candidate.py --help` 提供离线候选打包入口。
必须显式提供固定的完整 SHA、制品映射和来源记录，且使用干净的交接源码仓库。
工具不会执行编译、烧录、上传或发布，也不会读取设备认证头文件。

工具核对来源记录中的输入哈希，生成源码 ZIP、逐文件 SHA256 和候选 ZIP，
随后实际读取 ZIP 核对文件集合与校验值。输出必须是新目录，不覆盖旧包。
Windows 只收录程序根目录的 exe/dll/运行元数据和 data 资源；浏览器运行档案、
缓存、日志、PDB、本地认证文件和 AI 工作记录不作为交付内容。

源码过滤不是秘密检测器。源码仓库必须先完成交接审查；生成候选包也不代表
第三方许可全部通过。具体未决项以根目录 `THIRD_PARTY_NOTICES.md` 为准。
客户端包除 `data/flutter_assets/NOTICES.Z` 外，还应附带锁定依赖的许可清单和
适用的原生 SDK notices；`collect_flutter_notices.py` 提供前者的收集入口。

## 烧录与复核

1. 保存现有可用包和它的 manifest；不要只靠文件名判断版本。
2. 确认硬件是 Crabit V2、STM32L432CBU6 256 KiB，核对两个固件的完整哈希。
3. STM32 用既有受支持烧录流程；BW16 用已有 STM32 控制的烧录桥或文档里的
   Arduino 流程，不改 BOOT、电源、UART、OLED 交接或 Flash 布局。
4. 只由操作者烧录、复位、上电；一次替换一端并记录对应文件。
5. 检查表盘/设置、BLE 开关及客户端往返、BW16 进入退出、Wi-Fi、USB CDC/键盘、
   电池供电休眠/运动唤醒及唤醒后插 USB。记录每项通过、失败或未测。
6. 失败时保留失败包和复现步骤，用保存的同一套回退文件恢复，不混用另一条
   历史实验分支的镜像。完整步骤见[构建与烧录](guide/build-and-flash.md)。

正式公开发行还要求：组合制品的对应源码可取得，第三方分发条件已满足，
认证配置不会变成所有公开设备共用的秘密，且清单准确列明已测与未测。
