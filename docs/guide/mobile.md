# Crabit 手机应用

Crabit 手机应用是 Flutter 客户端：它提供设备连接入口、本地模型预览、设置和诊断界面。看到一个页面或按钮，只能说明客户端有对应界面；具体操作是否到达手表、被固件接受并产生效果，需要看返回结果和对应硬件验证。

## 运行桌面版本

需要已安装 Flutter SDK，以及 Windows 桌面构建所需的 Visual Studio C++ 工具链。仓库包含 Windows、Android、iOS、macOS、Linux 和 Web 平台工程，但这不等于这些平台都已构建或实机验证。Windows 是本指南的入门路径：

```powershell
cd apps/mobile
flutter pub get
flutter run -d windows
```

若 Flutter 尚未启用 Windows 桌面支持，先按 Flutter 官方环境说明配置本机工具链；不要因为平台目录存在就推断应用在该平台可用。首次依赖解析需要网络或已缓存的包。常用静态检查：

```powershell
flutter analyze
flutter test
```

## 页面与数据边界

- **设备**：连接、配对状态和只读诊断入口。打开应用本身不应被理解为已经连接。只有明确发起连接后才会扫描/连接；设备状态、业务认证和回显验证是不同阶段。
- **USB 工具**：编辑、组合并保存本地脚本，通过当前 RAM 脚本协议上传、运行、停止和读取状态。需要配套固件及明确操作，先在自己的电脑上使用无害文本验证。旧 Flash 脚本执行器和擦写入口仍未启用，不能用旧命令代替 RAM 协议。见 USB RAM 脚本。
- **无线记录**：用于查看诊断记录与相关工具界面；页面存在不代表手机已抓取到设备数据，也不代表 Wi-Fi 已连接或受控。
- **设置**：能否读写设备设置取决于当前协议和固件路径。只有收到并识别设备业务结果才能称为已应用；传输层 ACK 或发送成功不是设置成功的证明。
- **调试**：面向开发检查，不应将其当作普通用户的产品操作承诺。

脚本库、配对辅助数据及诊断记录使用应用本机的 Hive 存储；部分客户端偏好使用本地偏好存储。它们不会因此同步到远程数据库。卸载、清除应用数据或更换设备可能使本地数据消失。BLE 广播中的 Crabit UUID 和应用层配对流程也不保证操作系统已建立蓝牙系统级绑定。

## 模型与传感器

设备页的 3D 表盘和 OLED 预览运行在客户端本地，不是从手表实时读取的屏幕镜像。Windows 上的 NanoUI 桌面模拟器会运行本地 UI 核心；其中无线、传感器等菜单动作可能只是占位或模拟行为，不能据此认定手表执行了相同操作。单独的模型查看页同样是静态本地模型。

“IMU 倾斜”数据路径使用加速度/重力方向计算相对 roll、pitch；当前数据路径没有可用陀螺仪/磁力计航向，因此 yaw 不代表真实绝对朝向，不能把它描述为完整六轴/九轴姿态追踪。坐标方向、延迟和无线链路表现仍需在目标设备上验证。

## 当前 BLE 状态说明

设置页的“记住设备并在前台恢复连接”是可选策略，不是后台无限扫描；默认关闭。
客户端记住设备也不能唤醒已经断电的 BW16。有限重试、连接和认证仍是不同状态，不承诺下次启动必然自动连上。

当前链路使用六位应用验证码，不走历史 `ATTACH` 或 `PAIR/ALLOW`。先打开手表蓝牙，再在 App 发起连接并输入设备码；保存后后续连接可自动发送已保存值。具体入口、设备码配置与更改 App 保存码的区别，见 [首次连接图文](../../showcase/docs/connect.md)。不要将设备码写入公开文档、截图或提交。

验证码不是 BLE SMP/bond，也不提供链路加密或抗监听、抗重放保证。当前普通 BLE 启动与基本客户端操作有用户实机反馈；旧 ATTACH 问题和旧配对截图不能代表当前版本的状态。协议与限制见 验证码说明。

## 无硬件预览与学习路线

Windows 的模型预览复用 STM32 产品 App，由桌面内存适配器运行；表盘使用电脑时间，天气使用预览数据服务，不是实体手表屏幕流。8px 中文由仓库内 Fusion Pixel 点阵字库生成，其他字号仍按桌面资源配置生成。硬件字体与模拟资源分别输出，不互相覆盖。

- [快速玩起来](../../showcase/docs/start.md)：成品手表与 App 的操作入口。
- [开发环境](../../showcase/docs/setup.md) → [第一个 App](../../showcase/docs/first-app.md)：先在 Windows 跑通 NanoUI，再修改界面。
- [系统调用链](../../showcase/docs/system-walkthrough.md) → [Flutter 开发](../../showcase/docs/flutter-development.md)：区分本地预览、BLE、UART 与固件业务结果。

Windows 固定交付入口仍指向已归档的验收包，不会因源码合并自动替换为新构建。开发预览与验收 App 的路径区别见 Windows 交付说明。

普通 Windows 启动命令只运行 Flutter 客户端，不会自动刷写、复位或给手表上电。任何固件更新和实体操作都由用户执行。
