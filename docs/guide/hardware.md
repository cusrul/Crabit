# 硬件与设备边界

本文说明仓库源码面向的设备，不代替原理图、BOM、装配说明或电气设计审查。
已从维护者的 AD 原生归档整理出[可编辑硬件设计快照](../../hardware/altium/crabit-v2/README.md)，包含两张原理图、PCB 与随包元件库，文件/路径校验通过；AD 复开、独立环境与第三方许可核对尚未完成。它还不是足以让第三方照单复刻的制造发布包；不要根据模型或固件反推接线后直接供电。

## 主要组成

| 部分 | 源码能确认的情况 | 使用注意 |
| --- | --- | --- |
| STM32L432 | CubeMX 历史器件名为 STM32L432KBU6，作者实物已更换为 256 KB Flash 器件 | 先核实自己板上的实际型号和容量，不按历史 `.ioc` 名称烧录 |
| RTL8720DN / BW16 | Arduino AmebaD，目标板配置 Ai-Thinker BW16 | 独立编译；Flash 存储空间不等于应用连续可用空间 |
| 电源 | AXP2101 管理路径 | 不随意修改寄存器、上下电时序或默认电流设置 |
| 显示 | 128×64 单色 OLED，支持既有两端接管流程 | 同一时刻的显示所有权需要协调，不同时驱动总线 |
| 输入 | 产品按键与 PAT9125 相关输入代码 | 引脚、电平和实际装配需以对应板资料为准 |
| 运动数据 | QMI8658 相关驱动 | 当前数据路径启用加速度，陀螺仪输出为零；不能宣传完整姿态追踪 |
| 其他传感器 | 包含 BMP280 相关 App/驱动代码 | 源码存在不等于每块板都装配、正常初始化或校准 |
| USB | STM32 USB Device，保留 CDC 与固定文本键盘 Composite 候选 | 不是通用脚本执行器，也不能破坏烧录与恢复入口 |

## STM32 存储配置

当前链接器的 MEMORY 声明是 Flash 256 KB、RAM 64 KB、RAM2 16 KB。
这是构建配置，不是对换芯实物容量或可用 RAM 的测量，不能相加后当作容量验收依据。
这是现有实物换芯后的有意配置。若重新由 CubeMX 生成工程，不能因为历史器件名称指向较小容量就覆盖链接器，
也不能把当前 ELF 用于容量不足的原版芯片。板卡确认与备份应先于任何烧录。

## BW16 的 2 MB 为什么不能全部塞应用

Flash 还包括启动、镜像槽、配置和持久区。当前保护规则以实际打包镜像 `km0_km4_image2.bin` 为对象：

- 镜像从物理偏移 `0x6000` 开始。
- 先遇到的受保护位置是 `0xFC000`，对应现有 UART/settings 保留区。
- 已核对的 SDK 普通 FTL 起点是 `0x102000`；它与前一个保留区不是同一概念。
- 当前严格镜像长度目标为 `0xF4000`，不能因 Arduino 显示“最大 2 MB”就忽略它。

这些地址属于当前工程/SDK 配置，不是所有 BW16 的通用分区标准。
关闭 OTA 菜单不会自动把第二镜像槽合并给应用；本项目没有因此修改 SDK 分区。
具体检查入口见[构建与烧录](build-and-flash.md)。

## 连接、烧录和恢复

集成手表里的 STM32 与 BW16 通过内部 UART 直接连接。不能把另一块独立 BW16 开发板的外部串口接线经验照搬到手表。
Windows 的 COM 编号由当前枚举决定，不是项目固定常量。先辨认设备与接口，再选择工具。

任何修改前至少保留已知可用的成对固件、源码 SHA、烧录参数和连接说明。
操作供电、复位、进入烧录模式与刷写均由设备操作者执行。无法确认恢复路径时，不应尝试改变启动或 Flash 配置。
