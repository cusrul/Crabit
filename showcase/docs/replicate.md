## 先说结论

维护者已补充 AD 原理图和 PCB 视图，可先阅读[芯片与传感器分工](hardware-map.md)。这些截图可用于识别器件与预留，但不是完整制造包；以下固定源码快照的资料盘点仍只描述该历史快照。MMC5693NJ 磁力计虽画在设计中，当前未安装、未写驱动。

这份仓库快照包含 Crabit 的双芯片固件和开发说明，但**不是可直接下单、焊接并上电的硬件复刻包**。本文核对的源码快照是 `0487fb753d1c0eee717c66b77bab61aab86448f1`；它是软件版本标识，不是 PCB 版本，也不是已发布的成对固件。

## 仓库里实际有什么

| 文件或目录 | 能确认的用途 | 不能据此推断 |
| --- | --- | --- |
| `firmware/stm32/` | STM32L432 端的 CubeMX、HAL、FreeRTOS、USB 与 NanoUI 工程 | 完整原理图、板框、网络表、接插件位置或装配版本 |
| `firmware/rtl8720dn/NanoUI/` | Ai-Thinker BW16（RTL8720DN）端的 Arduino 工程；入口为 `NanoUI/NanoUI.ino` | 它与 STM32 共用同一套 SDK，或可直接用于任意 BW16 接线 |
| `libraries/NanoUI/`、`firmware/shared/` | 共享 UI 核心与双端通信/数据契约 | 板级电气设计或完整物料清单 |
| `firmware/stm32/crabit_st.ioc`、`firmware/stm32/STM32L432KBUx_FLASH.ld` | STM32 工程配置与链接布局 | 这两份文件不是可制造的 PCB 设计资料 |
| `docs/guide/hardware.md`、`docs/guide/build-and-flash.md` | 已记录的器件类别、存储边界和固件构建入口 | 逐步装配、接线或首次上电操作卡 |

在该快照的受版本控制文件中没有 `hardware/` 目录；没有找到原理图、可编辑 PCB、Gerber/钻孔文件、BOM、贴片坐标、封装库或板级机械文件。代码和下列器件名称只能帮助识别系统组成，不能代替这些制造资料。

源码文档将当前 STM32 板描述为 `STM32L432CBU6`、256 KB Flash 配置，同时记录历史 `.ioc` 器件名为 `STM32L432KBU6`。这是需要按实物和设计版本核实的差异，不要仅凭旧工程名改芯片配置或下单。文档还记录 BW16/RTL8720DN、AXP2101、128×64 单色 OLED、PAT9125 相关输入、QMI8658 加速度路径和 BMP280 驱动；其中“有驱动/代码”不证明每块板都装了相应器件。

## 先把版本对上

- 分别记录软件提交、PCB 修订号、BOM 修订号和实物 MCU 型号。`0487fb7` 只标识源码快照，不能代替后三者。
- 不要把历史 `.ioc` 名称、当前链接器容量和未知实物混为一个版本；需要由硬件负责人确认板卡与固件配置对应关系。
- STM32 与 BW16 是独立工程、独立工具链和独立产物。当前仓库没有指定可供新用户直接刷写的稳定成对固件包。
- BW16 的编译成功不等于上传对象已确认。检查必须针对最终实际要上传的同一份打包镜像；IDE 上传镜像的闭环流程在现有文档中仍未完成。

## 从零复刻的安全顺序

1. **冻结设计版本。** 先取得硬件负责人发布的板号、修订记录、原理图与 PCB 源文件，以及与之对应的制造输出。没有这些文件时，不要从照片、固件引脚或 `.ioc` 反推线路并投板。
2. **核对制造包后再下单。** 使用同一修订的板框、层叠与制造说明、钻孔/外形文件及电气检查结果。加工参数必须来自该设计的正式发布包；本仓库没有给出可安全套用的参数。
3. **按已批准 BOM 采购。** 核对准确料号、封装、方向和获批替代料，并确认电池、显示器、连接器及机械件属于同一板卡修订。不要因驱动存在就假定某传感器已装配。
4. **按该版本装配文件焊接。** 使用匹配的封装、坐标、装配图和经负责人确认的工艺；缺少极性/方向标记或装配资料时先停下，不用猜测补齐焊接步骤。
5. **上电前先做无电检查。** 对照该版原理图和检查标准核对器件方向、焊桥、连接器与网络连续性。首次供电所需的输入范围、极性、限流值、测量点、上电次序及停止条件必须由硬件负责人给出；仓库没有这些数值，因此不能据此接电试机。
6. **最后匹配固件并验收。** STM32 从 `firmware/stm32` 的 CMake 工程构建；BW16 从独立 Arduino 工程构建并使用打包的共享 NanoUI 库，BW16 构建需串行。记录源码/工具版本、产物路径与校验值，并确认待操作的确是对应板卡版本的文件。构建或镜像检查不等于实体板验收；刷写、复位和供电由设备操作者按已验证的版本操作卡执行。

## 还需要硬件负责人提供

- 带修订号的原理图、PCB 源文件、制造输出、板层/工艺说明，以及相关文件可公开/再分发的授权。
- 完整 BOM（制造商料号、封装、方向、获批替代料）、贴片坐标和装配图。
- 实物板版本、各连接器与引脚定义、显示器/电池/机械规格，以及 STM32 型号与链接配置的对应确认。
- 与该板版本对应的焊接/装配要求、无电检查项目和首次上电限值与步骤。
- 经过确认的 STM32/BW16 固件组合、SDK/工具版本、最终上传文件身份、恢复方式和由操作者完成的验收记录。

资料齐备前，可以阅读[从开箱开始](start.md)或[开始二次开发](develop.md)了解产品与软件；固件版本及恢复边界见[固件更新与恢复](update.md)。这些入口不替代缺失的硬件设计和上电操作资料。
