# Crabit V2：Altium 工程整理版

打开本目录的 **`Crabit_OpenHardware.PrjPcb`**，不要打开历史临时副本。

## 内容与来源

```text
Crabit_OpenHardware.PrjPcb    工程入口
l432.SchDoc                  STM32、供电和传感器原理图
nrf8720dn.SchDoc             BW16、显示与接口原理图
Crabit_V2.PcbDoc             PCB 设计
libraries/                  原生归档收集的 17 个 SchLib、28 个 PcbLib
IMPORT-REPORT.json           文件校验与整理记录
```

来源为维护者使用 AD22.5.1 原生 Project Packager 生成的 `Crabit (2026-10-26 21-41-06).zip`。压缩包 SHA256、当前文件 SHA256 见清单。8份经过显示配置路径脱敏的文件另保留 `native_archive_sha256`，不能将其当前哈希当作原生 ZIP 的原样复制哈希。原始 ZIP 留在维护者本地，不重复提交约195 MB的压缩包。

本目录约217 MB，其中45个库约202 MB。**这是原生归档的完整库集合，不是已经提取好的最小项目库。** 有些库包含项目未使用的通用器件；本轮保留原包内容，没有擅自裁剪或重新构造专有库文件。

## 做了什么、没有做什么

- 两张原理图及38个未脱敏库保持原生包的二进制内容。
- PCB及7个封装库只清空 `2DCONFIGFULLFILENAME` 显示配置路径值，使用等长度空白保留容器和记录长度；其他字节不变，包括元件、网络、布线、焊盘、规则及模型数据。详见 `DISPLAY-METADATA-REPORT.json`。
- 仅把工程配置中的文件引用与内嵌输出目标改为包内相对路径。
- 去掉22条 ZIP 未收录的历史制造输出引用，避免把旧 Gerber/钻孔/DRC 报告当作当前资料；没有删除原工程中的历史文件。
- 中文 ZIP 文件名按实际 UTF-8 字节恢复，避免解包后乱码导致库找不到。
- 不包含原工程 History、旧 PCB1/PCB2、SolidWorks 临时文件、AI 对话或旧的脚本整理候选。

原理图/库内部仍可能保留第三方来源库名和参数。此次仅处理上述已定位的显示配置字段，不能据此认定所有模型关联已独立，也不是对全部第三方元数据的脱敏声明。

## 已验证与待验证

已通过：原生 ZIP CRC、当前48份二进制文件清单校验、工程相对引用目标存在、工程文本无盘符绝对路径、未混入历史制造输出；8份脱敏文件的非目标数据流逐字节不变，已清除本次定位的当前电脑账户路径。

原生检查：AD22.5.1已打开备份工程；脱敏PCB的2D、3D正常显示，7份脱敏库全部载入，当前库中的封装可见。没有逐个渲染全部库内的所有封装。

**尚未完成**：两张原理图的原生显示验收、集成库编译、原理图与 PCB 一致性/DRC、与原库隔离的独立环境检查、全部3D模型逐项核对。

在AD里编辑后重新保存，可能再次写入该操作者的本地显示配置路径；后续分发前仍需复查。

文件检查命令（不需要 AD）：

```text
python tools/verify_altium_package.py
```

检查后续编辑时可更新版本和清单，不要为了通过哈希检查将设计强行退回旧版。当前清单仅证明本次导入快照。

## 打开和后续检查

1. 使用 Altium Designer 22.5.1 或兼容版本打开工程入口；工程文档引用应全部在本目录内。
2. 分别打开两张原理图、PCB 2D/3D，确认无丢失模型或载入错误。不要自动执行 Update PCB、重新编号或从旧库批量更新设计。
3. 可使用 Design → Make Integrated Library，或分别 Make Schematic Library / Make PCB Library，生成项目专用库。检查同名符号、封装变体与引脚映射后再替换完整库集合。
4. 在与本机原库隔离的环境打开验证；只换目录但仍安装原库，不足以证明独立性。

## 发布前边界

库和模型的版权/再分发许可见 [`libraries/README.md`](libraries/README.md)，尚未统一授权。不能因为文件进了仓库就给第三方素材统一套上项目许可证。

PCB上存在封装或原理图画有器件，不代表产品全部装配。MCU历史符号名、实际256 KB器件、未装配预留、BOM和产品说明须按维护者实际板卡核对。此整理不宣称它们已经一致，也不作为直接投板依据。
